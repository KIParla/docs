= Collection Automation

`KIParla-collection` is rebuilt *locally*, with `tools/regenerate_local.py`, after one or more modules publish a release, and then pushed.
This page describes what the rebuild does and how to run it.

== Overview

The rebuild used to be a GitHub workflow fired by every module release. When several modules were released together, the runs pushed to the same branch at the same time and most were rejected, so the rebuild now runs on the maintainer's machine, in one pass, and nothing is pushed before it has been inspected.

== Running it

[source,bash]
----
python tools/regenerate_local.py            # commits locally, prints what to push
python tools/regenerate_local.py --push     # also pushes and creates the collection release
----

`KIParla-collection` and `KIParla-NoSketch-Data` must be clones on a clean `main`, next to `tools/` and `moduli/<Module>` (or pass `--root`). See `tools/docs` (`scripts.adoc`, `regenerate_local.py`) for the options.

== What the build does

. Reads each module at its latest release tag (`git archive`: the working trees of the modules are not touched).
. Copies all `.tsv` files into `tsv/` and all `.eaf` files into `eaf/`.
. Regenerates `linear-enriched/` and `linear-orthographic/` by running `tsv2formats.py` on every TSV file.
. Merges `participants.tsv` and `conversations.tsv` from all modules using `tools/merge_metadata.py`, and regenerates `csv-metadata.json`.
. Bumps the patch version in `CITATION.cff`, commits and tags.
. Regenerates the NoSketch data (`KIParla-NoSketch-Data`): the corpus of each module and the aggregate `KIParla` corpus.

The build is idempotent: if no files changed, no commit (and no new version) is made.

== Metadata merging

Metadata is merged by `https://github.com/KIParla/tools[tools/merge_metadata.py]`.

The script normalises column differences between modules before merging:

[cols="1,1,1", options="header"]
|===
| Module | Participants columns | Note
| KIP | `school-region`, no `study-level` | `school-region` is renamed to `birth-region`; `study-level` is left empty
| KIPasti | `birth-region`, `study-level`, `L1` | `L1` is dropped from the merged output
| ParlaBO | `birth-region`, `study-level`, `L1` | `L1` is dropped from the merged output
| ParlaTO | `birth-region`, `study-level` | —
|===

The merged `participants.tsv` keeps these columns: `code`, `occupation`, `gender`, `conversations`, `birth-region`, `age-range`, `study-level`.

The merged `conversations.tsv` keeps these columns: `code`, `type`, `duration`, `participants-number`, `participants`, `year`, `collection-point`.

Rows with duplicate `code` values are deduplicated, keeping the first occurrence (module order: KIP → KIPasti → ParlaBO → ParlaTO).

== Adding a new module

To include a new module in the collection build:

. Add the module to `MODULES` in `tools/regenerate_local.py`.
. If the new module has non-standard column names in its metadata, add a rename mapping to the `COLUMN_RENAMES` dict in `tools/merge_metadata.py`.

== Troubleshooting

Build failed during metadata merge::
Check that all module repos have a `metadata/participants.tsv` and `metadata/conversations.tsv` with a `code` column.
If a module added or renamed a column, update `COLUMN_RENAMES` or the target column lists in `merge_metadata.py`.

Build triggered but no changes committed::
All files were already up to date. This is expected behaviour.

The script stops with "checkout `main` first"::
`KIParla-collection` or `KIParla-NoSketch-Data` is on another branch or has uncommitted changes to tracked files.
